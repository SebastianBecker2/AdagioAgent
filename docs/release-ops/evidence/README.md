## Release Ops Evidence Repository

This folder stores release- and pilot-support evidence referenced by operations
sign-off records.

### Category structure

- `support-bundles/`: support bundle manifests and exported summaries.
- `correlation-traces/`: correlation-ID trace artifacts linking extension errors
  to backend logs.
- `rollback/`: rollback rehearsal records and outputs.
- `upgrade-validation/`: completed upgrade checklist outputs and notes.
- `indexes/`: per-sign-off evidence index files generated by script.

### Conventions

- Prefer repository-relative evidence paths in sign-off records.
- Keep evidence names version-scoped where possible.
- Use immutable external URIs only when repository storage is not possible.
- Approved external URI formats: `https://`, `s3://`, `gs://`, `az://`, and
  UNC paths (`\\server\share`).

Generate a release evidence index scaffold with:

```powershell
.\scripts\generate-evidence-index.ps1 -Version <semver>
```

### Update cadence

- Update the evidence index whenever a support bundle is regenerated for the
  same release version.
- Update the `Support bundle:` entry in the index in the same commit where the
  regenerated bundle manifest is added.
- Re-run tagged-release validation checks before final sign-off closeout:

```powershell
.\scripts\check-signoff-evidence-index-reference.ps1
.\scripts\check-evidence-index-content.ps1
```

### Retention and archive checklist

1. Confirm the retention window has elapsed and no active support incident
  requires in-repo raw evidence files.
2. Archive raw evidence artifacts to approved immutable storage.
3. Keep in-repo sign-off records and evidence index files, updating archived
  artifact entries with archive URI and archival date.

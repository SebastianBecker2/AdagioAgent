# HTTPS Setup on Linux

This document explains how to configure TLS for the Adagio Machine Agent on
Linux. The agent requires HTTPS by default; the `install.sh` script handles
this automatically, but the steps below describe what it does and how to
replicate them manually.

---

## Quick start (automated)

If you installed the agent with `installer/linux/install.sh`, a self-signed
certificate and API key were generated automatically. Skip to
[Trusting the certificate on the client](#trusting-the-certificate-on-the-client).

---

## Manual certificate setup

### 1 — Generate a self-signed PFX certificate

```bash
# Variables
CERT_DIR="/etc/adagio-machine-agent/tls"
CERT_PFX="${CERT_DIR}/agent.pfx"
CERT_PASSWORD="$(openssl rand -base64 24 | tr -d '\n')"

sudo mkdir -p "${CERT_DIR}"

# Generate RSA key and self-signed certificate
TMP_KEY=$(mktemp)
TMP_CERT=$(mktemp)

sudo openssl req -x509 \
    -newkey rsa:4096 \
    -keyout "${TMP_KEY}" \
    -out "${TMP_CERT}" \
    -days 3650 \
    -nodes \
    -subj "/CN=adagio-machine-agent/O=AdagioAgent" \
    -addext "subjectAltName=IP:127.0.0.1,DNS:localhost"

# Package as PKCS#12 (PFX) — the format Kestrel/ASP.NET reads
sudo openssl pkcs12 \
    -export \
    -out "${CERT_PFX}" \
    -inkey "${TMP_KEY}" \
    -in "${TMP_CERT}" \
    -passout "pass:${CERT_PASSWORD}"

rm -f "${TMP_KEY}" "${TMP_CERT}"

sudo chmod 0640 "${CERT_PFX}"
sudo chown root:adagio-agent "${CERT_PFX}"

echo "Certificate password: ${CERT_PASSWORD}   (save this)"
```

### 2 — Write `appsettings.json`

Create or update `/etc/adagio-machine-agent/appsettings.json`:

```json
{
  "Urls": "https://127.0.0.1:5443",
  "SecurityOptions": {
    "RequireHttps": true,
    "RequireApiKey": true,
    "ApiKey": "<your-api-key>",
    "ApiKeyHeaderName": "X-API-Key",
    "HttpsCertificatePath": "/etc/adagio-machine-agent/tls/agent.pfx",
    "HttpsCertificatePassword": "<password-from-step-1>"
  }
}
```

Set restrictive permissions so only the service account can read secrets:

```bash
sudo chmod 0640 /etc/adagio-machine-agent/appsettings.json
sudo chown root:adagio-agent /etc/adagio-machine-agent/appsettings.json
```

### 3 — Restart the service

```bash
sudo systemctl restart adagio-agent
sudo systemctl status adagio-agent   # should show "active (running)"
```

## Trusting the certificate on the client

The VS Code extension connects from the developer machine. Because the
certificate is self-signed, you must either:

### Option A: Add the certificate thumbprint to the extension settings

1. Export the certificate in PEM format:
   ```bash
   sudo openssl pkcs12 -in /etc/adagio-machine-agent/tls/agent.pfx \
       -clcerts -nokeys -passin "pass:<password>" | \
       openssl x509 -fingerprint -sha256 -noout
   ```
2. Copy the `SHA256 Fingerprint=...` value (without colons) into the
   extension setting `adagioAgent.tlsCertificateFingerprint`.

### Option B: Import the certificate as a trusted CA on the developer machine

Export the certificate:
```bash
sudo openssl pkcs12 -in /etc/adagio-machine-agent/tls/agent.pfx \
    -clcerts -nokeys -passin "pass:<password>" \
    -out /tmp/adagio-agent.crt
```

Then copy `/tmp/adagio-agent.crt` to the developer machine and:
- **Windows**: Double-click → "Install Certificate" → "Local Machine" →
  "Trusted Root Certification Authorities"
- **macOS**: Open in Keychain Access, drag to "System", set to "Always Trust"
- **Linux**: `sudo cp adagio-agent.crt /usr/local/share/ca-certificates/; sudo update-ca-certificates`

## Certificate renewal

The self-signed certificate generated by `install.sh` is valid for 10 years
(3650 days). To renew:

1. Stop the service: `sudo systemctl stop adagio-agent`
2. Delete `/etc/adagio-machine-agent/tls/agent.pfx`
3. Re-run `install.sh` (the script regenerates the certificate when the PFX
   is absent, preserving the existing `appsettings.json` API key)
4. Re-distribute the new certificate to client machines (see above)

---

## Disabling HTTPS (development / lab only)

Set `RequireHttps: false` in `appsettings.json` and change `Urls` to
`http://127.0.0.1:5080`. **Do not use HTTP in production** — the API key
would be transmitted in clear text.

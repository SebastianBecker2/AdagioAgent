## Support Bundle Manifest Schema

The support bundle generated by `scripts/collect-support-bundle.ps1` includes a
`manifest.json` file that describes collected artifacts and collection notes.

### Top-level fields

- `GeneratedAtUtc`: UTC timestamp when bundle generation completed.
- `BundleDirectory`: absolute output directory path for this bundle.
- `ApiBaseUrl`: API base URL used for endpoint collection.
- `OfflineMode`: whether endpoint collection was skipped.
- `ArtifactSchema`: required vs optional artifact categories.
- `IncludedFiles`: artifacts actually written for this bundle.
- `Notes`: collection warnings and non-fatal issues.

### Artifact categories

Required artifacts (must be present for a valid bundle):

- `manifest.json`
- `machine-info.json`
- `service-status.json`
- `application-events.json`

Optional artifacts (present depending on runtime mode/config):

- `health.json`
- `ready.json`
- `diagnostics-status.json`
- `diagnostics-export-metadata.json`
- `offline-note.txt`
- `extension-output-metadata.json`

### Extension output metadata option

When `-ExtensionOutputPath` is provided, the script writes
`extension-output-metadata.json` with:

- provided path
- resolved path (if resolvable)
- existence state
- last-write timestamp (when available)

This allows support workflows to trace where extension diagnostic exports were
captured without embedding sensitive content in the bundle.
